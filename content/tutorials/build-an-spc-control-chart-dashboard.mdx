A control chart answers one question: has this process changed, or is it just noise? Every process varies a little from part to part. Statistical process control (SPC) measures how much it varies when nothing is wrong, draws limits around that, and flags the moment the data stops behaving that way, usually well before a single part fails inspection.

```text
Measurements (one value per sample, in time order)
        |
        | Calculated column: moving range between neighbors
        |
Baseline (first 20 samples): center line, sigma, control limits
        |
        | Measures: z-score per sample, Western Electric rules over a window
        |
Dashboard (I chart with signals, moving range chart, Cp / Cpk)
```

Download the data: [measurements.csv](/downloads/spc-control-chart-dashboard/measurements.csv), or paste the table below into a `.csv` file yourself.

---

## What You're Building

A one-page control chart dashboard answering the questions a quality review actually asks:

- Is the process stable, or has something changed?
- When did it change, and which rule caught it?
- Is the point-to-point variation itself getting worse?
- How capable is the process against its specification?

```text
+---------------------------------------------------------------+
| Center Line |  UCL  |  LCL  |  Signals  |   Cp   |   Cpk      |
+---------------------------------------------------------------+
|  I chart: Sample Value, Center Line, UCL, LCL, Signal Point   |
+---------------------------------------------------------------+
|  Moving range chart              |  Table: sample, value,     |
|  (MR, average MR, MR UCL)        |  z-score, Signal Rules     |
+---------------------------------------------------------------+
```

Scan the column and nothing jumps out. Every reading is inside the spec; the highest is 24.38, still 0.12 under the upper limit. An inspection report for this shift would say "30 of 30 good." `SampleNo` matters more than it looks. Control charts are about **order**: the moving range compares each reading to the one before it, and the run rules look at the last 3, 5, or 8 readings. Every DAX step below finds "the previous sample" or "the last eight samples" by doing arithmetic on `SampleNo`, so it has to run 1, 2, 3… with no gaps, in time order.

## Step 2: Load the Data

**Get Data > Text/CSV**, and name the table `Measurements`. Check the types in Power Query: `SampleNo` is a **Whole Number**, `Value` is a **Decimal Number**, and `MeasuredAt` is a **Date/Time**.

If your own data has no sequence column, make one in Power Query: sort by the timestamp first, then **Add Column > Index Column > From 1**, and rename it `SampleNo`. Sorting first is the important part; an index on unsorted rows gives every later step the wrong neighbors.

## Step 3: The Moving Range

An individuals chart has one reading per point, so there's no subgroup to measure spread within. Instead, it measures the spread between neighbors: the **moving range**, the absolute difference between each reading and the one before it.

**Table tools > New column**:

```dax lineNumbers
Moving Range =
VAR ThisSample = Measurements[SampleNo]
VAR PrevValue =
    MAXX (
        FILTER ( Measurements, Measurements[SampleNo] = ThisSample - 1 ),
        Measurements[Value]
    )
RETURN
    IF ( NOT ISBLANK ( PrevValue ), ABS ( Measurements[Value] - PrevValue ) )
```

For each row, `FILTER` finds the row whose `SampleNo` is one less, and `MAXX` pulls its value out (there's only one row, so `MAX` is just a way to turn it into a scalar). The first sample has no predecessor, so its moving range is blank, not zero. A zero would tell the average that two readings were identical. See [Calculated Columns](/docs/dax/calculated-columns) and [Variables](/docs/dax/variables) if either pattern is new.

The first few rows:

| SampleNo | Value | Moving Range |
|---|---|---|
| 1 | 24.02 | *(blank)* |
| 2 | 23.87 | 0.15 |
| 3 | 23.85 | 0.02 |
| 4 | 24.01 | 0.16 |

## Step 4: Center Line and Control Limits From a Baseline

Control limits describe the process when it's behaving normally, so they have to come from a stretch of data where it was. Here that's the first 20 samples, the **baseline**. Everything after is **monitoring**: compared against those limits, but not allowed to move them.

```dax lineNumbers
Sample Value =
AVERAGE ( Measurements[Value] )

Center Line =
CALCULATE (
    AVERAGE ( Measurements[Value] ),
    REMOVEFILTERS ( Measurements ),
    Measurements[SampleNo] <= 20
)

Average Moving Range =
CALCULATE (
    AVERAGE ( Measurements[Moving Range] ),
    REMOVEFILTERS ( Measurements ),
    Measurements[SampleNo] <= 20
)

Sigma =
[Average Moving Range] / 1.128

UCL =
[Center Line] + 3 * [Sigma]

LCL =
[Center Line] - 3 * [Sigma]
```

[REMOVEFILTERS](/docs/dax/filter-functions#removefilters) clears whatever sample the chart is currently on, and the `SampleNo <= 20` filter puts back just the baseline. So `Center Line` returns the same number at every point on the chart, which is what draws it as a flat line. Without `REMOVEFILTERS`, the "center line" at each point would just be that point's own value. See [CALCULATE](/docs/dax/calculate) for how the two filter arguments combine.

`1.128` is the SPC constant **d2** for ranges of two readings. The average range of two values from a normal distribution is 1.128 standard deviations, so dividing by it converts the average moving range into sigma. (Many textbooks fold it into one number: 3 / 1.128 = 2.66, so the limits are center ± 2.66 × MR̄. Same result.)

With this data:

| Measure | Value |
|---|---|
| Center Line | 24.006 |
| Average Moving Range | 0.128 |
| Sigma | 0.114 |
| UCL | 24.348 |
| LCL | 23.665 |

Notice the control limits are much tighter than the spec (23.5 to 24.5). The spec says what's *acceptable*; the control limits say what's *normal for this process*. A reading of 24.38 is a perfectly good part, and also a sign that something has changed.

## Step 5: Flag the Western Electric Rules

A point beyond 3 sigma is the obvious signal, but a small shift often never produces one. Instead, it shows up as a pattern: too many points on one side, or a cluster just inside the limit. The four **Western Electric rules** are the standard set of patterns:

| Rule | Signal | What it usually means |
|---|---|---|
| 1 | One point beyond 3σ | A sudden, large change or a one-off event |
| 2 | 2 of 3 in a row beyond 2σ, same side | A moderate shift |
| 3 | 4 of 5 in a row beyond 1σ, same side | A small, sustained shift |
| 4 | 8 in a row on the same side of center | A shift too small for the other rules |

All four are easiest to test in units of sigma, so start with a z-score: how many sigmas each point sits from the center line.

```dax lineNumbers
Z Score =
DIVIDE ( [Sample Value] - [Center Line], [Sigma] )
```

Then one measure checks all four rules for the current point, looking back over the last eight samples:

```dax lineNumbers
Signal Rules =
VAR k = MAX ( Measurements[SampleNo] )
VAR Pts =
    ADDCOLUMNS (
        FILTER (
            ALL ( Measurements[SampleNo] ),
            Measurements[SampleNo] > k - 8 && Measurements[SampleNo] <= k
        ),
        "@z", CALCULATE ( [Z Score] )
    )
VAR z = MAXX ( FILTER ( Pts, Measurements[SampleNo] = k ), [@z] )
VAR Last3 = FILTER ( Pts, Measurements[SampleNo] > k - 3 )
VAR Last5 = FILTER ( Pts, Measurements[SampleNo] > k - 5 )
VAR R1 = ABS ( z ) > 3
VAR R2 =
    ( z > 2 && COUNTROWS ( FILTER ( Last3, [@z] > 2 ) ) >= 2 )
        || ( z < -2 && COUNTROWS ( FILTER ( Last3, [@z] < -2 ) ) >= 2 )
VAR R3 =
    ( z > 1 && COUNTROWS ( FILTER ( Last5, [@z] > 1 ) ) >= 4 )
        || ( z < -1 && COUNTROWS ( FILTER ( Last5, [@z] < -1 ) ) >= 4 )
VAR R4 =
    k >= 8
        && ( COUNTROWS ( FILTER ( Pts, [@z] > 0 ) ) = 8
            || COUNTROWS ( FILTER ( Pts, [@z] < 0 ) ) = 8 )
VAR Fired =
    SUBSTITUTE (
        TRIM ( IF ( R1, "1 " ) & IF ( R2, "2 " ) & IF ( R3, "3 " ) & IF ( R4, "4 " ) ),
        " ", ", "
    )
RETURN
    IF (
        HASONEVALUE ( Measurements[SampleNo] ) && NOT ISBLANK ( z ) && Fired <> "",
        "Rule " & Fired
    )

Signal Point =
IF ( NOT ISBLANK ( [Signal Rules] ), [Sample Value] )
```

How it works, piece by piece:

- `k` is the sample the chart is on. `ALL ( Measurements[SampleNo] )` ignores that filter so `FILTER` can see the window of the last eight samples, `k - 7` through `k`.
- `ADDCOLUMNS` computes each window sample's z-score. `CALCULATE ( [Z Score] )` triggers [context transition](/docs/dax/calculate#context-transition), so each row's z-score is evaluated for *that* sample, not for `k`. See [ADDCOLUMNS & SELECTCOLUMNS](/docs/dax/addcolumns-selectcolumns).
- `Last3` and `Last5` are just the tail of that window, and each rule is a count of rows past a threshold. Rules 2 and 3 also require the current point itself to be out in the zone, so the flag lands on the point that completes the pattern, not on an innocent point after it.
- `Fired` builds a label like `Rule 1, 2, 3`; `HASONEVALUE` keeps it off the total row.

`Signal Point` returns the value only where a rule fired. Plotted as a second series with markers and no line, it puts a red dot on exactly the points that matter.

With this data, the baseline has no signals at all (S07 dips to −2.25σ, but one point isn't a pattern). Then:

| Sample | Value | Z Score | Signal Rules |
|---|---|---|---|
| S19 | 24.27 | 2.32 | |
| S20 | 23.94 | −0.58 | |
| S21 | 24.38 | 3.29 | Rule 1, 2, 3 |
| S22 | 24.23 | 1.97 | Rule 3 |
| S23 | 24.09 | 0.74 | |
| S24 | 24.38 | 3.29 | Rule 1 |
| S25 | 24.13 | 1.09 | Rule 3 |
| S26 | 24.14 | 1.18 | Rule 3 |
| S27 | 24.27 | 2.32 | Rule 3 |
| S28 | 24.07 | 0.56 | Rule 4 |
| S29 | 24.15 | 1.26 | Rule 3, 4 |
| S30 | 24.35 | 3.02 | Rule 1, 3, 4 |

S21, the first reading after the baseline, breaks three rules at once: it's past the UCL (rule 1), it's the second of the last three beyond 2σ along with S19 (rule 2), and it's the fourth of the last five beyond 1σ (rule 3). From there, nine of the ten monitoring readings are flagged. By S28, eight in a row have sat above the center line (rule 4), which is about as clear a statement as a control chart makes: **the process mean has moved up**. The shift turns out to be about 0.21 N·m, roughly two sigma.

## Step 6: The Moving Range Chart

The I chart watches the process *level*. The moving range chart watches its *noise*: if neighboring readings start jumping around more, the process has lost consistency even if the average hasn't moved.

```dax lineNumbers
Moving Range Value =
AVERAGE ( Measurements[Moving Range] )

MR UCL =
3.267 * [Average Moving Range]

MR Signal Point =
IF ( [Moving Range Value] > [MR UCL], [Moving Range Value] )
```

`3.267` is the constant **D4** for ranges of two readings. The moving range chart's lower limit is zero (D3 is 0 at this size), so there's no `MR LCL` to draw.

Here `MR UCL` is **0.420**. One moving range crosses it: S21, at 0.44, the jump from 23.94 to 24.38. That's the step itself showing up as one unusually large difference between neighbors. After S21 the moving ranges settle back down, which says the process didn't get noisier. It moved to a new level and stayed there.

## Step 7: Process Capability, Cp and Cpk

Capability compares the process's natural spread to the specification. It only makes sense for a stable process, so calculate it from the same baseline the limits came from:

```dax lineNumbers
Cp =
DIVIDE ( 24.5 - 23.5, 6 * [Sigma] )

Cpu =
DIVIDE ( 24.5 - [Center Line], 3 * [Sigma] )

Cpl =
DIVIDE ( [Center Line] - 23.5, 3 * [Sigma] )

Cpk =
MIN ( [Cpu], [Cpl] )
```

**Cp** asks whether the spread *would* fit if the process were perfectly centered: spec width over six sigma. **Cpk** asks whether it *does* fit where the process actually sits: the distance from the mean to the nearer spec limit, in units of three sigma. Cp ignores centering; Cpk doesn't.

On the baseline, Cp is **1.46** and Cpk is **1.45**, so the process is centered and comfortably above the common 1.33 minimum.

Now suppose the shift stays. Over S21–S30 the mean is 24.219, and the spread hasn't changed. Cp stays at 1.46, because spread is all it measures. But Cpk falls to **0.82**: the upper spec limit is now only 2.5 sigma from the mean, and at that distance you'd expect about 7 parts in 1,000 above 24.5. Not one of the 30 readings is out of spec yet. That's the gap SPC is for.

The spec limits are typed in as numbers here. If they live in a table (a characteristics or part-number table, say), replace `24.5` and `23.5` with `MAX` of those columns.

## Step 9: Other Chart Types

Individuals and moving range is the right chart when each sample is one measurement. Two other common cases use the same structure with different math:

**X̄ and R chart**: several measurements per sample (say, five parts measured every hour). Each subgroup is one point; the chart plots its mean, sigma comes from the average subgroup range divided by d2 *for that subgroup size* (2.326 for five), and the limits for a subgroup mean are three times sigma divided by √n. The rules measure is identical; it just counts subgroups instead of samples.

**p chart**: a pass/fail count per sample (defectives out of inspected). The center line is the overall defective rate, and sigma is `SQRT ( p × (1 − p) / n )`, which means **the limits change with every sample size**: wider for a small batch, tighter for a big one. The z-score approach in Step 5 handles that automatically, because each point is divided by its own sigma.

The [Control Chart Builder](/tools/control-chart-builder) generates the full DAX for all three, with your table name, subgroup size, baseline, and spec limits filled in, and draws the chart from pasted data so you can check your Power BI version against it point by point. Paste this tutorial's 30 readings in and you'll get the same limits, the same signals, and the same Cpk.

## Common Mistakes

### Calculating the Limits From All the Data

It seems more thorough to use every reading. Drop the `SampleNo <= 20` filter and the limits widen: the center line moves up to 24.077, sigma grows to 0.132, and the UCL rises to **24.474**. The shifted readings now set the limits they're being judged by. S21, S24, and S30 all fall back inside, and **every signal from the shift disappears**.

Worse, the chart now flags the wrong stretch. With the center line pulled up, S01 through S09 all sit below it, so rule 4 (eight in a row) fires on S08 and S09: false alarms during the period when nothing was wrong. Pick the baseline from a period you have reason to believe was stable, and freeze it. Recalculate only after a deliberate, confirmed change to the process.

### Using the Standard Deviation for Sigma

```dax lineNumbers
Sigma (Wrong) =
CALCULATE ( STDEV.S ( Measurements[Value] ), REMOVEFILTERS ( Measurements ) )
```

`STDEV.S` measures the spread of everything, including the shift, so it mixes "the process moved" into "the process is noisy." Over all 30 readings it gives 0.162 instead of 0.114, and the UCL climbs to 24.563, **above the upper spec limit**. A chart like that can never flag anything before parts are already bad. The moving range only compares neighbors, so a shift barely affects it: one big jump at S21, then back to normal. That robustness is exactly why individuals charts use it.

### Putting the Sample Label on the Axis

The rules measure looks back over neighboring `SampleNo` values. With `Measurements[Sample]` on the X-axis instead, every point also carries a filter like `Sample = "S21"`, which `ALL ( Measurements[SampleNo] )` doesn't remove. The window's other samples evaluate as blank, and rules 2, 3, and 4 quietly never fire; only rule 1 still works. Put `SampleNo` on the axis. If you want the labels shown, put `Sample` in the tooltips.

### Gaps in SampleNo

Both the moving range column and the rules window find neighbors by arithmetic: `SampleNo - 1`, `k - 8`. If samples 14 and 15 were deleted as bad readings, sample 16's moving range comes out blank, and every window around the gap is two samples short. Re-index after filtering rows, not before.

### Confusing Spec Limits With Control Limits

Drawing 23.5 and 24.5 on the chart as if they were control limits turns it into an inspection chart: it flags a problem only once a part is already bad. Keep both if you like, but in different colors and with different names. The control limits (23.665 to 24.348 here) come from the process; the spec limits come from the drawing.

### Reporting Cpk for an Unstable Process

Cpk assumes the process is one stable distribution. Calculated across S01–S30, this process gives a Cpk that's neither the old 1.45 nor the new 0.82, and describes a process that never existed. Fix the signals first, or calculate capability separately for each stable period.

## Tutorial Checklist

- `SampleNo` runs 1, 2, 3… in time order with no gaps, and it's on the chart's X-axis.
- The moving range is blank for the first sample, not zero.
- The center line and sigma come from a fixed baseline, with `REMOVEFILTERS` so they're flat across every point.
- Sigma is the average moving range / 1.128, not the standard deviation.
- `Signal Rules` flags S21 with rules 1, 2, and 3, matching the table in Step 5.
- Cp and Cpk come from the baseline, and only get reported while the chart shows no signals.
- Spec limits and control limits are shown differently, if both are shown at all.
